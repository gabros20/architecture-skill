# Architecture skill — FIND-SKILLS channel corpus

**Channel:** open agent-skills ecosystem (skills.sh / `npx skills find`).
**Scope:** every existing agent-skill relevant to software architecture / system design / ADR / DDD / API & event design / distributed systems / cloud & well-architected / threat modeling / agentic-system architecture / mobile & frontend architecture / platform engineering — to (a) study structure for dedup/learning and (b) harvest substantive content.

**Method:**
- Discovery done serially by the channel lead via `npx skills find "<query>"` across ~50 keyword variants (broad, synonyms + angles) plus `--owner`-scoped sweeps of named orgs (anthropics, vercel-labs, obra, wshobson). No parallel searches against the CLI. Raw output saved to scratchpad `raw-search*.txt` / `raw-owners.txt` / `raw-wshobson.txt`.
- 302 unique skill@count entries surfaced in the broad sweep; owner-scoped sweeps surfaced the true heavyweights (install counts an order of magnitude higher than the generic search reports).
- Ranked on install count + lane-coverage; picked finalists (see `scratchpad/arch-research/finalists.md`).
- 4 Sonnet workers deep-read DISJOINT repo sets in parallel (clone/read only — no rate-limited search). Worker reports under `scratchpad/arch-research/reports/skills-{A,B,C,D}.md`, folded below.

**Coverage-honesty note:**
- `npx skills leaderboard` is not a command (only `find`); leaderboard-by-install was approximated via broad + owner-scoped `find`. The generic `find` under-reports install counts vs owner-scoped `find` for the same skill (e.g. wshobson/agents@architecture-patterns shows 19.5K owner-scoped vs not surfaced generically) — so absolute ranking across the whole ecosystem is approximate.
- `obra/superpowers` and `vercel-labs/agent-skills` had NO architecture-specific skills (they lead on brainstorming/TDD/debugging and frontend/react-native respectively) — noted, not collected deeply.
- Long tail (~250 lower-install skills) was catalogued by name/count but NOT deep-read; finalists were the ~50 highest-value across lanes.

### Group 6 — Data / schema architecture

**wshobson/agents @postgresql-table-design (dir: postgresql)** · [border→data] · MIT — 22.1K installs; densest rules-engine reference of the whole set
Source: plugins/database-design/skills/postgresql/ (single 203-line SKILL.md, all DO/DO-NOT rules)
- PK: `BIGINT GENERATED ALWAYS AS IDENTITY` default, UUID only for global-uniqueness/opacity. Normalize-3NF-first, denormalize only w/ measured ROI. FK columns need MANUAL indexes. Type defaults TIMESTAMPTZ/NUMERIC/TEXT/BIGINT. **DO-NOT list**: no bare `timestamp`, no `char(n)`/`varchar(n)`, no `money`, no `timetz`, no `serial`. Gotchas: identifier case-folding, UNIQUE allows multiple NULLs (`NULLS NOT DISTINCT` PG15+), MVCC dead-tuple/vacuum. Index taxonomy (B-tree/Composite leftmost-prefix/Covering INCLUDE/Partial/Expression/GIN/GiST/BRIN). Partitioning RANGE/LIST/HASH >100M-row threshold. Playbooks: update-heavy (hot/cold split, fillfactor=90), insert-heavy (COPY, UNLOGGED staging), upsert (`ON CONFLICT`+`EXCLUDED`), safe evolution (`CREATE INDEX CONCURRENTLY`). JSONB GIN recipes.
